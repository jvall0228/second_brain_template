# 10. Validate semantics

*Section 10 of the [`brain` spec](../SPEC.md); section numbers are stable and `§N.x` references across the spec point at these files.*

## 10.1 Rule sources

Tag namespace membership is read **at runtime** from the authoritative table in [CONVENTIONS](../../../../00_Meta/CONVENTIONS.md#tag-namespaces) — `brain` hardcodes no generic taxonomy. Mechanically: take the first markdown table after the `## Tag Namespaces` heading; skip the header and separator rows; for each data row, the **namespace** is the first backtick-quoted token in column 1 with any trailing `/*` removed; if column 3's cell text begins with `Free-form` (case-insensitive), the namespace is **open** (any value passes); otherwise the namespace is **closed** and its value list is the backtick-quoted tokens in column 3. Applied to the current table this yields closed `audience`, `type`, `workflow`, `status`, `restricted` and open `topic`, `project`, `area`; §27 separately resolves the two identity namespaces. A missing or unparseable table, or a row yielding no namespace, is a validate **error** (`conventions-table-unreadable`), never a silent pass.

## 10.2 Checks

**Errors** (exit 1): missing frontmatter; missing/null `title` or `updated`; a missing, null, or **empty** `tags` list (`tags: []` declares no tags and fails the same `missing-tags` check; the §10.3 template-placeholder exemption is per-value, and an empty list has no values to exempt, so it fires in `09_Templates/` too); `not-readable` (§3 read failure — `validate` reports it as the note's only finding, suppressing the derived frontmatter-field checks, and `not-utf8` behaves the same way; every other command skips the file); `invalid-updated`; any §4 `frontmatterErrors` entry except the warning-mapped ones below; a frontmatter tag not slash-delimited, in a namespace absent from the conventions table, or (for closed namespaces) not in the value list — **frontmatter tags only; `bodyTags` are informal and never checked**; a filename-convention violation; `future-updated` — a valid `updated:` date strictly after the §15.3 horizon (today in the configured `timezone`, or host-today plus one day of grace when no timezone is configured; template placeholder values are already exempt via `invalid-updated`); an unresolved or ambiguous internal link (placeholders exempt); `path-collision` — two corpus paths equal under the §6 folding rule, which cannot co-exist on default macOS/Windows filesystems. Secret-scanning findings (§10.5) are also errors.

**Filename convention:** applies to the **basename** of note files only (directories and assets are not checked). A note basename must match `^[a-z0-9]+(-[a-z0-9]+)*\.md$` — all-digit segments are allowed, so dated notes like `2025-01-15.md` and `2024-01-review.md` pass. Exceptions per [CONVENTIONS](../../../../00_Meta/CONVENTIONS.md): `AGENTS.md`, `CLAUDE.md`, `README.md`, and the PARA entity entrypoints `PROJECT.md`, `AREA.md`, and `RESOURCE.md` at any level; the 14 exact-case framework paths registered in `CORE_FRAMEWORK_PATHS`; periodic tokens `YYYY-W##-review.md` and `YYYY-Q#-review.md`; `SKILL.md` inside `10_Agents/skills/` (Agent Skills format, M6); `SPEC.md` inside `10_Agents/tools/` (canonical tool contracts — this document). Case variants of a registered framework path fail even when the lowercase basename would otherwise match kebab-case; the exception does not apply to an identically named note elsewhere.

**Agent Skills contract (`10_Agents/skills/`, added at M6 per the implementation plan; nesting added 2026-09-04):** a **skill directory** is any directory under `10_Agents/skills/`, at any depth, holding a `SKILL.md`; a directory that holds only skill directories and optionally a `README.md` is a **group** (e.g. `setup/`). Every note under the skills root must belong to a skill directory (itself or an ancestor) or be a group's `README.md`; otherwise its top-level directory is `skill-missing`. Each `SKILL.md`'s frontmatter must carry — in addition to the vault contract — an Agent Skills `name` equal to the directory name (`skill-name-mismatch`) and a non-empty `description` string (`skill-missing-description`); a skill directory without a `SKILL.md` is `skill-missing`. All three are errors.

**Warnings** (exit 2 if no errors): `case-mismatch`; `unsupported-block-reference`; `tags-not-a-list`; `duplicate-key`; `restricted-link` — a note **without** `restricted/private` in its frontmatter tags links to or embeds a resolved note **with** it; per the 2026-08-24 privacy policy (conventions § restricted/private) this is an **informational provenance check**, not a containment ban — the message asks whether nearby prose carries private substance (which requires the note to carry `restricted/private` too, per R7-R8) and states that a bare link alone never propagates the tag. `restricted-transition` — a tracked note's frontmatter `restricted/private` state differs from its HEAD baseline (KTD4/R8): one advisory warning per transition, reporting the path and the direction (`added` | `removed`) plus a fixed reminder that generated surfaces (committed index, AYMT, Home, artifacts) change inclusion and need their owning regeneration — never any title or body prose. Detection requires a trustworthy baseline: git must run, the vault root must be the repository toplevel (compared by inode, so path case cannot silently disable detection), and the note must exist in HEAD (untracked new notes are not transitions); when git is unavailable, the vault is not a repo, or a baseline read fails, transition detection is skipped silently and normal validation is unaffected. Both the worktree and the staged index are compared against HEAD — a staged-only flip still warns at the pre-commit moment — and renames are followed (`-M`), so a flip riding a `git mv` keeps its old-path baseline; tree paths are handed back to git as the raw bytes it emitted, with NFC normalization used only for index lookups. Cost is bounded to two rename-aware `git diff --name-status` prefilters (every changed or renamed note is a candidate — deliberately no `-G` content filter, because a duplicate-`tags:`-block flip or a gitattributes `-diff`/binary rule can change the parsed restriction state without the tag's literal text appearing in the diff) plus one `git cat-file --batch -Z` subprocess supplying every baseline and staged blob at once (a constant number of subprocesses per validate, regardless of how many notes changed), all under the local git timeout (more generous than the remote-safety budget so a cold-cache whole-tree diff cannot silently disable detection). Legacy `unresolved-fragment` remains visible in records/migration blockers without a validate finding during the WP8 compatibility window. `missing-author` — a `02_Inbox/` agent draft with no non-empty `author:`; `task-invalid-date`; the §14 curation signals; and every §27 Project/Area entity-contract finding. `invalid-expires` remains an error. Placeholders are counted/reported but exempt.

**`--check-index`:** re-serialize the index corpus per §8.2 and byte-compare against the committed `vault-index.json`; a mismatch or missing file is an error ("stale index — run `brain index`").

## 10.3 Exemptions

- `09_Templates/**`: any frontmatter value (or list item) containing `{{` is deemed to satisfy the required-field, format, and membership checks it would otherwise fail — the placeholder **is** the value. The exemption is per-value, not per-note: a template-directory note without placeholder values (e.g. the section README) is fully checked. The glob is recursive, so `09_Templates/variants/` (issue #12 specialization sources) is covered the same way — variant files carry placeholder frontmatter like the templates they mirror. Placeholder **links** are exempt everywhere by construction (§5.1).
- `CLAUDE.md` at the vault root: exempt from all frontmatter checks (one-line adapter, PRD §8.2).
- No directory is exempt from `restricted-link`. A blanket `07_Archives/**` carve-out was considered and rejected: archived reports are still appended to, and a row that summarizes a private note carries its substance. Archive-lane links that carry no substance (a filing row naming a path and its tag changes, an evidence citation) are ordinary standing warnings for the §10.6 baseline, recorded only after an owner-reviewed audit.

## 10.4 Output and exit codes

Human output: one line per finding — `ERROR <path>[:<line>] <rule>: <message>` / `WARN …` — sorted by path, then line (findings without a line first), then rule; a final summary line `N errors, M warnings`. By default the warning lines and the `M` count cover only warnings **not covered by the committed baseline** (§10.6); when a baseline is loaded the summary appends ` (K baselined, hidden; --all shows them)` and, if the baseline holds entries no longer observed, `; S baseline entries cleared — run \`brain validate --write-baseline\``. `--all` bypasses the baseline and prints every warning as before. JSON: `{"baselined": [...], "errors": [...], "warnings": [...]}` where each finding is `{"line": int|null, "message": str, "path": str, "rule": str}`; `warnings` holds the new findings and `baselined` the covered ones (`--all` moves everything into `warnings`).

Exit codes: `0` clean · `1` at least one error · `2` new warnings only (with `--all`, any warnings). A vault whose only warnings are baselined exits `0`. The pre-commit hook and CI (M5.4) block on exit 1 and pass on 0/2.

## 10.5 Secret scanning

PRD §16.2's never-commit-credentials rule is enforced by `validate` itself, so the existing hook/CI/agent-stop chain blocks credentials with no new wiring. Every finding is an **error** (rule `secret-<name>`, exit 1); severity is fixed by design.

**Scope.** Every file in the **working corpus** (§2) — notes *and* assets — one pass per `validate` run. The §2 pruning already keeps the scan safe by construction: dot-directories (`.git/`, `.obsidian/`, `.vscode/`, …), every `10_Agents/tools/*/tests/` tree, and the committed `vault-index.json` never enter the corpus. Binary files are skipped by NUL-byte sniff (a `0x00` byte in the first 8 KiB); text is decoded UTF-8 with replacement characters and newline-normalized per §3, so line numbers match the rest of `validate`. Frontmatter and code blocks are **not** excluded — a credential is a credential wherever it sits.

**Rule table.** Detection is **data-driven**: the module-level `SECRET_RULES` table in `brain.py` — `(name, compiled pattern)` pairs — is authoritative for the exact patterns; extending detection is a table edit (add a row there and a row here in the same commit; #22's self-improvement loop and upstream sync extend it the same way). The table below describes each rule in words (deliberately not as literal match-bait):

| Rule name | Detects | Pattern (in words) |
|-----------|---------|--------------------|
| `aws-access-key-id` | AWS access key IDs | `AKIA` followed by exactly 16 uppercase letters/digits, word-bounded |
| `github-token` | GitHub tokens | prefix `ghp_`, `gho_`, or `github_pat_` followed by 20+ word characters |
| `slack-token` | Slack tokens | `xox` + one lowercase letter + `-` + 10+ token characters |
| `private-key` | PEM private-key headers | five dashes, `BEGIN`, an optional uppercase label, `PRIVATE KEY`, five dashes |
| `generic-credential` | literal credential assignments | a key named like api-key / secret / token / password (case-insensitive), then `:` or `=`, then a **quoted** literal of 12+ token characters containing at least one digit |
| `high-entropy-string` | long opaque literals (the one conservative entropy heuristic) | `:` or `=`, then a **quoted** run of 40+ base64 characters containing lowercase, uppercase, and a digit (padding `=` allowed) |

The two assignment rules require the value to be *entirely* quoted token characters, and the entropy heuristic requires mixed case plus a digit — so prose, link markup, bare git SHAs (lowercase hex has no uppercase), and long URLs (contain `:`/`.`/`?` outside the charset) never flag; tuned to zero false positives on this repo's own tree, which the test suite pins with a repo self-scan.

**Allowlist.** A line is exempt when it carries an HTML comment containing the token `brain:allow-secret-pattern` — marker and pattern on the **same line**. The committed marker is the audit trail: documentation *about* token shapes stays possible, and every suppression is greppable. There is no file- or directory-level allowlist.

**Output.** Findings follow §10.4 (`ERROR <path>:<line> secret-<name>: …`) but the message **never echoes the matched text** — it names the rule and points at the marker escape, so a real credential is not additionally copied into terminals, CI logs, or agent transcripts.

**Backstop.** GitHub-side secret scanning + push protection (issue #24 item 3) is a repository setting owned outside this tool — it catches formats this table doesn't know, including in git history. Tracked separately; `validate` neither depends on nor replaces it.

## 10.6 Warning ratchet (baseline)

Long-lived vaults accumulate standing warnings — informational `restricted-link` notices on Areas that legitimately cite private records, `oversized` notes awaiting a split, closed Projects awaiting an approved archive move. Printed on every commit they bury the one warning that is new. The **baseline** turns `validate` into a ratchet: standing warnings are recorded once, and each run reports only what the baseline does not cover.

**File.** `10_Agents/tools/brain/validate-baseline.json`, committed, generated **only** by `brain validate --write-baseline` (hand edits and generic writes are forbidden, as for every generated file). Shape: `{"schemaVersion": 1, "warnings": [{"count": int, "message": str, "path": str, "rule": str}, …]}`, rows sorted by (path, rule, message), serialized with `indent=1`, `sort_keys`, `ensure_ascii=False`, trailing newline. `--write-baseline` runs the full validation and, **only when it found zero errors**, writes the file from **all** current warnings, prints `<path>: N warnings baselined`, and exits `0`. With any error it prints the errors, leaves an existing baseline byte-for-byte unchanged (and creates none), and exits `1`: a run that fails validation never persists anything. **Secret backstop:** because the file is pruned from the corpus and never rescanned, a warning whose message or path matches any §10.5 secret rule is refused — the write is skipped and the run exits `1` — so credential-shaped text (a link label, say) cannot be stored there. The write is atomic (same-directory temporary file and rename) through an authenticated parent: every component under the vault root must be a real directory and the target a regular file or absent; a symlink anywhere on the path is refused. `--json` reports `{baselined, errors, path, refusal, written}`. It is a deliberate act — run it after the owner has accepted that the remaining warnings are standing debt, never inside a hook.

**Identity.** A warning's ratchet key is `(path, rule, message with every whitespace-delimited digit run folded to #)` — `(?<!\S)\d+(?!\S)`. Line numbers are excluded and standalone numbers folded so that a note growing (`oversized: 21857 bytes / 158 lines`) or a link moving down the file never turns a standing warning into a new one, while a different link target, a different rule, or a different note always does. Path-embedded digits (`05_Areas`, `2026-08-31`) are not standalone and survive the fold. Equal keys are counted: a baseline row with `count: 2` covers the first two occurrences in §10.4 order; a third is new.

**Matching.** A missing, unreadable, wrong-`schemaVersion`, or malformed baseline means no baseline: every warning is new (the pre-ratchet behavior). Malformed is any departure from the shape above — `warnings` not a list, a row that is not an object, a non-string or empty `path`/`rule`, a non-string `message`, or a `count` that is not a positive integer (booleans included) — and the whole file is then ignored rather than partially applied, so a broken baseline can only reveal warnings, never suppress them. Baseline rows that no current warning matches are **stale**; they are counted in the summary as cleared but never fail the run — the ratchet only tightens by explicit `--write-baseline`. Errors are never baselined.

**Not covered.** The baseline is a reporting filter, not a suppression: `run_validate` still returns every warning, `brain report` and the §14 curation signals see the full set, and `--all` prints it. The pre-commit hook still passes on exit 2, so a new warning still never blocks a commit; what changes is that the owner now sees it.
