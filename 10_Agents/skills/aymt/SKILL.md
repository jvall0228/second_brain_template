# Actions You May Take

Use the deterministic `brain aymt` collector. Treat suggestions as options for owner review, never permission to send, publish, purchase, delete, or contact anyone.

## Workflow

1. Preview with `brain aymt` or inspect the same candidates with `brain aymt --json`.
2. Explain the highest-ranked suggestions with their recorded why-now, next step, caveat, and sources. This is a complete internal view of eligible tracked work, including private work; ranking and display caps still bound the brief. Preserve source classification and provenance when reusing its substance. Do not add foreign-environment context.
3. When the owner explicitly asks to refresh the canonical snapshot, run `brain aymt --write`. This dedicated command is the only approved writer for `00_Meta/AYMT.md`; never hand-edit it.
4. Verify freshness with `brain aymt --check`, or inspect the read-only `fresh` field in `brain aymt --json`. Exit 0 from `--check` means the generated bytes match current tracked inputs, date, and selected environment metadata. An edit or render date alone does not establish freshness; recheck after the final source/index update.

The default path is local-only and never invokes GitHub, a connector, or the network. A caller may separately provide a strict sanitized issue snapshot with `--github-input /absolute/path.json` or `--github-input -`; brain validates it and computes canonical GitHub issue URLs. Do not pass arbitrary connector output or URLs.

## Safety contract

- Private notes and valid links to private notes remain eligible. Generated AYMT/Home, Archives, Templates, seeded examples, untracked files, and every environment note body are excluded before candidate construction. The collector classifies and transforms the same authenticated source bytes.
- `privacySources` in JSON and `privacy-sources` in generated frontmatter include eligible inputs contributing text, ranking, counts, and health signals, including undisplayed candidates. Private renders inherit `restricted/private`; effective classification follows current source dependencies. Missing or invalid provenance is unknown for public-only admission and does not prohibit internal use.
- Projects come only from the canonical Project/Area registry. Both the generic task and Project candidate paths require Project-directory actions to be open tasks under `## Next Actions`; future start/scheduled dates and inactive Project directories stay excluded. An empty section is valid. Criteria and historical tasks remain available to ordinary queries. Supporting notes and stale NOW bullets do not create duplicate Projects; estimated and overdue targets remain explicit. See the [Project and Area Contract](../../docs/project-area-contract.md#next-actions).
- Internal inclusion authorizes no sending or public export. Public-only synthesis starts in a fresh policy-only context with admitted sources under the [privacy contract](../../../00_Meta/restricted-private.md#public-only-synthesis); filtered retrieval cannot cleanse earlier private context. If isolation is unsupported, report that without synthesizing. Notifications and public-only consumers retain their destination-specific restrictions.
- Unconfigured environment state is useful and valid. A malformed or ambiguous configured selection fails without exposing selection detail.
- `--check` and preview are zero-write. `--write` may change exactly `00_Meta/AYMT.md`, refuses foreign or modified content, and fails closed when safe mutation is unavailable.
- Source links in the generated file remain source-relative Markdown; sanitized GitHub issues use computed canonical HTTPS links.
